# Zmiany wprowadzone w przeglądzie planu

_Co krytyczny recenzent poprawił w szkicu planu i dlaczego (po angielsku)._

1. Stage order: HealthKit is now Stage 3 and APNs notifications Stage 4. HealthKit has the longest feedback loop (7 days on the real phone), does not depend on the unproven HTTP/2-from-Edge path, and changes what the 09:00 push contains. The draft scheduled Stage 5 widget installs during the HealthKit 'no Xcode' soak week. Now the phone is 'frozen' that week, and notifications and widgets are built on the Simulator. Simulator receives real sandbox APNs pushes on Apple silicon (Pushwoosh, citing Xcode 14 release notes).
2. Device-secret provisioning redesigned. The native app generates the secret; web registers only SHA-256 via register_device(p_device_id, p_secret_hash, …). The secret never reaches JS or a server response. This removes the 'return secret once' handshake and the prev_hash/prev_valid_until rotation window. device_secrets keeps only secret_hash. Added device_revoke_self(p_secret) for offline sign-out, and 'any 28000 = signed out' handling.
3. Added a Keychain wipe on first launch, keyed by an App Group UserDefaults flag. Keychain items survive app uninstall (DTS, forums thread 36442). Without the wipe, a reinstall would reuse a stale device secret.
4. Dropped migration M4 (apns_jwt_cache table) and renumbered M5–M7 to M4–M6. Apple's doc says the 20-minute token-refresh limit applies per connection ('if you use a new token more than once every 20 minutes on the same connection'), so an in-memory per-isolate cache is correct. A DB table would hold a credential for no benefit. Fallback to a cache table only if 429 TooManyProviderTokenUpdates appears.
5. Shortcut API (api_tokens, log_habit, token_habits, ingest_metrics) is now frozen with no changes. The draft refactored ingest_metrics into _ingest_core and made log_habit write origin 'siri' and ingest_metrics write 'shortcut', which is work M6 then deletes, on a table with 0 rows. Legacy entries keep origin NULL (old rule). The origin enum drops 'shortcut', and 'siri' now means native App Intents.
6. device_apply_entries 'stale' now applies only to non-monotonic ops (no/set/skip/clear). complete/add are monotonic and never stale. Otherwise a HealthKit ingest that bumps updated_at would make a queued 'Zrobione' from a notification come back as stale. Health upserts use 'where value is distinct from' so they don't bump updated_at needlessly. Added 'ignored' result for 'no' on a positive value, and entry_adds retention of 35 days (more than the 30-day date window).
7. Fixed a wrong claim: 'health habits are not in reminders today' is only true for summary, time-of-day and habit reminders (logic.ts filters !i.habit.source). The 'yesterday' reminder uses yesterdayGap, which does NOT filter by source. The plan now states that, keeps it, and adds the stale-sync note plus a 'open Nawyki to resume Health' push after 3 days without sync. DTS recommends a server push because a manual app launch clears the force-quit flag (forums 803365).
8. Fixed the quiet/comeback push mapping. quietMessage() returns only title/body, so it must also return the easiestHabit id for the HABIT category. src.ts must also select entries.origin and load devices; the draft only mentioned lib/data/snapshot.ts.
9. APNs fallback rule: with push_target=native, Web Push is also sent when no active device exists OR devices.last_seen_at is older than 7 days. APNs reports uninstalls late, so the draft's acceptance criterion 'after deleting the app the next reminder arrives via Web Push' was not reliably testable. It was replaced with 'after Revoke device in PWA…'.
10. Lock-screen widgets: the draft said they are preview-only. Apple docs list accessoryCircular and accessoryRectangular as interactive on iPhone, but buttons are inactive until the device is unlocked. The plan now offers a 'check next' button on the rectangular widget.
11. Controls: specified that ControlWidgetToggle uses a SetValueIntent and is made configurable with AppIntentControlConfiguration (HabitEntity parameter). Controls run while locked by default, and IntentAuthenticationPolicy can require unlock (Apple docs).
12. Widget/Control push corrected. Widget push is iOS 26+ (topic <bundle>.push-type.widgets, aps.content-changed). Control push is iOS 18+ (ControlPushHandler, apns-push-type controls, topic .push-type.controls). Both are budgeted and opportunistic. The draft said 'from iOS 26 types widgets/controls'.
13. Siri claim corrected. The draft said 'Siri AI in Polish works text-only' and cited thinkapple.pl, which could not be verified and whose URL suggests the opposite. Verified sources say the new Siri AI is unavailable in the EU (DMA dispute), and the iOS 27.1/27.2 language expansion excludes Polish (antyweb, benchmark.pl). Also noted that App Shortcuts need zero Shortcut setup, which respects the owner's refusal to use Shortcuts, and that the Action Button can be bound to a Control directly.
14. Service worker claim reframed. Forum thread 781744 is an unanswered user report, not evidence. DTS (thread 760767) says service workers work in WKWebView but Web Push does not. WebKit gates service workers on App-Bound Domains. Added Stage 0 Test 2 (offline cold start in WKWebView) because it decides the offline story. The Supabase domain was removed from WKAppBoundDomains: fetch is not navigation, so it is added only if the test shows blocking. Noted the side effect that no WKWebView can navigate outside the list (forums 770366).
15. Added Garmin as a likely data source. The repo mentions Garmin Connect in HealthSync.tsx and commits c88a939 and d8e6039. appleExerciseTime exists only with an Apple Watch, so 'Ruch' gets a Garmin variant via a new metric workout_min (sum of HKWorkout durations). Basen and Sleep note Garmin as a possible writer. Open question 1 now asks Watch vs Garmin.
16. Xcode 27 requirement: added Apple silicon only (no Intel) and macOS Tahoe 26.6+ (secondary source quoting Apple release notes). Added deployment target iOS 26.0 to avoid back-compat code, Developer Program enrollment lead time (~48h), and that Personal Team does not support Family Controls (forums 852204).
17. Region config: use vercel.json "regions": ["fra1"] (versioned and reviewable) instead of only the dashboard. Vercel docs confirm iad1 is the default for new projects. 'Done when' is now testable via the x-vercel-id header containing fra1.
18. Found via the Vercel MCP that the project has SSO Deployment Protection on all non-custom domains. Preview testing of /api/v1/snapshot and of web changes inside the shell therefore needs a custom alias (beta.nawyki.gmarczak.xyz, also in Debug-only App-Bound Domains) or the protection-bypass header.
19. Added Associated Domains webcredentials plus public/.well-known/apple-app-site-association for password AutoFill in WKWebView. Also added a proxy.ts matcher exclusion for .well-known (otherwise Apple's CDN gets redirected to /login), alongside the api/v1 exclusion.
20. Web shell gaps added. useAppBadge.ts uses navigator.setAppBadge, which is missing in WKWebView, so it now uses postNative('badge'). HabitTimer: JS is suspended in the background, so a native local notification is added, with optional mindful-session write needing NSHealthUpdateUsageDescription. pushSupport() returns 'ios-needs-install' in the shell. UA is extended via applicationNameForUserAgent (append, not replace) so isIos() keeps working. WKWebsiteDataStore.default() is now explicit.
21. device_snapshot must return the FULL entry history, because streakOf iterates from habit.startDate (lib/domain/progress.ts), plus note dates and moods (absence() uses them). Added a top-level 'habits' list to the snapshot JSON so HabitEntity/HabitQuery can see habits not required on yesterday, today or tomorrow. toEntry needs note:null. Entry.origin is optional, so CACHE_VERSION in providers.tsx must not change (a change would wipe the offline queue).
22. Internal _entry_* functions must insert user_id explicitly and compute 'today' from p_uid. habit_entries.user_id defaults to auth.uid() and set_entry relies on user_today()/RLS, which are NULL/bypassed in security-definer anon context. Public set_entry, add_entry and clear_entry keep signatures and grants. A rollback file holds copies of the current bodies from 20261024090000 and 20261025090000.
23. Added rollback/kill switch per stage, which the draft lacked. Mechanisms: supabase/rollback/*.down.sql outside the migrations folder (CI runs only migrations/*.sql); push_target=web; an APNS_ENABLED secret; Revoke device as the universal stop for native writes; clearing habits.source; delete by health_daily.device_id; cron.unschedule for Duolingo. M6 is explicitly marked non-additive and must also remove the matching assertions in supabase/tests/assertions.sql.
24. Made acceptance criteria testable. Snapshot latency is now p50 < 300 ms over 5 warm calls plus fra1 in x-vercel-id. 'behavior.sql passes unchanged' became 'CI database job green, existing set_entry/add_entry/clear_entry assertions unchanged'. Added scripts/register-test-device.mjs so Stage 1 can be tested before the shell exists. Added a Debug button that writes and removes sample swim and run workouts for the Basen test. Extended the login-persistence test to 8+ days to match the owner's 9-day silence and ITP's 7-day script-storage cap.
25. HealthKit details tightened against Apple docs. Register observers in didFinishLaunching; ALWAYS call completionHandler (3 misses stop delivery); stepCount is max hourly even with .immediate (doc, plus DTS April 2026 saying frequency is not guaranteed). Defined the 'final' day for health_synced_through. BGAppRefreshTask is no longer 'around 07:30': HealthKit data is unavailable while locked, so it mainly flushes the outbox. The outbox is now flushed on every background wake (HealthKit wakes double as a sync channel).
26. Notification details. The content extension needs UNNotificationExtensionCategory=MULTI and UNNotificationExtensionUserInteractionEnabled=YES. Deterministic op_id (UUIDv5 of apns-id + habitId) makes action retries idempotent. apns-collapse-id is limited to 64 bytes and payload to 4 KB. apns-expiration is best-effort. APNs stores only the last notification while offline. The .p8 is stored as single-line base64 in Edge secrets. The APNs key is team-scoped and Sandbox-only (Apple now restricts team keys per environment, max 2).
27. Stage 0 probe strengthened: sign a real JWT so the expected answer is {"reason":"BadDeviceToken"}, which proves both HTTP/2 and ES256 signing. Cited the Deno docs: fetch negotiates h2 via ALPN automatically. Supabase Edge Runtime is still unconfirmed, so the Vercel node:http2 relay fallback stays.
28. Screen Time experiment hardened. DeviceActivityMonitor network access is undocumented, and the Report extension is explicitly network-sandboxed (Apple docs). The design is now: write to App Group, try POST, and otherwise let the app flush on its next wake. Duplicate threshold callbacks are reported (forums 741133), hence deterministic op_ids. includesPastActivity must be set to true explicitly because the default is false since iOS 17.4 (forums 745675). Confirmed that Family Controls Development needs no Apple approval for Xcode installs in a paid team (Apple 'Configuring Family Controls').
29. Duolingo: owner's Mac curl is not sufficient. Stage 6 now starts with poll-duolingo in dry_run FROM Supabase, because the endpoint is unofficial with no 2026 sources and may treat datacenter IPs differently. Uses streakData.currentStreak.endDate and a deterministic op_id. M5 notes source_min=1 because habits_source_threshold requires it for check habits.
30. Capacitor facts updated: current major is 8 (8.5 shipped Aug 2026), Capacitor 9 is forecast for end of Nov 2026, and server.url's own doc comment says not for production. supabase-swift rejection rationale now cites Supabase's rotation and reuse-detection behavior (reuse outside the interval revokes the whole session). The 10 s default comes from a third-party source and is described as configurable.
31. Added an XcodeGen-vs-Xcode-27 compatibility risk (could not verify a release), with a fallback of committing the .xcodeproj using folder-synchronized groups.
32. Added an optional Stage 8 Notification Service Extension for the 09:00 push. It filters out habits already completed locally and tries a HealthKit read when unlocked, which DTS suggests in forums 803365.
33. Repo-name corrections. Sign-out lives in features/settings/sections.tsx and already uses signOut({scope:'local'}). The 'yesterday' reminder kind is 'yesterday' and time-of-day kinds are morning/day/evening (README and logic.ts). The M4 (health_v2) metric list must update HEALTH_METRICS and METRIC_INFO (Record type forces both); ingest_metrics stays frozen. Constraint names habits_source_check and health_daily_metric_check were confirmed as the auto-generated names of the inline column checks.
34. Open questions extended: Watch vs Garmin, Mac model (Apple silicon), whether the owner habitually force-quits apps (fatal for HealthKit background delivery), and consent to the soak-week phone freeze. Removed sources that were not evidence (forums 781744) or not verifiable (thinkapple.pl). Added verified Apple doc and forum URLs.
